## 这个目录是什么

这里把分散在互联网各处、由真人经营的个人站点收到一起，让人能找到它们、读到它们、订阅它们。每个站点都由维护者看过之后才收录，每一条都写明这是谁的站、主要在写什么或做什么。

<!-- STATS:START -->
- 目前收录 **50** 个站点，来自 **9** 个地区，使用 5 种语言写作。
- 其中 **19** 个提供 RSS / Atom 订阅源，可通过 [feeds.opml](https://realchendahuang.github.io/one-person-one-site/feeds.opml) 一次性导入阅读器。
- 内容形态：`blog` (33)、`digital-garden` (6)、`notes` (10)、`portfolio` (19)、`newsletter` (1)。
- 常见主题：`developer` (36)、`ai` (14)、`indie-hacker` (12)、`maker` (11)、`open-source` (5)、`writer` (5)、`designer` (4)、`tech` (3)。
<!-- STATS:END -->

每一个条目背后都是一个具体的人：一位制造业工程师在记录他的 AI 实验，一位室内设计师在写他边做设计边做产品的经历，一位大三学生在把自己的学习和项目铺成一座数字花园，一位资深工程师在整理 RAG 与后端的技术取舍。他们写的东西各不相同，共同点是把自己的东西放在自己的站点上，而不是只交给平台。

## 和其他目录有什么不同

整理个人博客的项目已经有不少，各有侧重：

- 想要一份尽量全的中文博客列表，可以看 [chinese-independent-blogs](https://github.com/timqian/chinese-independent-blogs)；
- 想让自己的博客加入站点之间的互访或长期承诺，可以看 [开往](https://www.travellings.cn/) 和 [十年之约](https://www.foreverblog.cn/)。

一人一站的做法是：

- **少而精。** 每个站点都人工核对，不符合标准的不收；收录后变成营销页的，会重新评估。
- **介绍人，不只列链接。** 每条都有一句客观的简介和标签，可以按作者身份和主题浏览。
- **不止博客。** 设计师、开发者、摄影师展示自己作品的个人站，同样在收录范围内。
- **方便订阅和复用。** 所有 RSS 打包成一个 OPML 文件，全部数据以 JSON 开放。

## 我们相信什么

**个人网站是互联网上少数真正属于你的地方。**

平台账号可能被限流、被封禁，规则也随时会变。自己的域名和站点不会：样子、排版、放什么内容都由你决定，它也可以安安静静地存在十年。

所以我们愿意花时间维护这份目录，让认真写东西、认真做东西的人更容易被找到。

> 一人一站不是要求每个人都去当全职站长。我们只想把那些已经在自己的站点上长期写作、长期创作的人找出来，介绍给更多读者。

## 收录标准

### ✅ 我们欢迎

| 类型 | 说明 |
|---|---|
| **独立博客 / Independent Blog** | 长期记录技术、思考、读书或生活的站点，有真实的作者在写。 |
| **数字花园 / Digital Garden** | 未完成但持续生长、互相链接的笔记与想法。 |
| **个人作品集 / Portfolio** | 设计师、开发者、摄影师、艺术家展示自己作品的个人站。 |
| **独立创作者主页 / Indie Maker** | 公开构建（Build in Public）的个人项目与探索记录。 |
| **个人知识库 / Knowledge Base** | 针对某个领域系统整理的公开笔记。 |

### ❌ 我们谢绝

- 公司官网、营销页、SaaS 产品落地页；
- 接单服务页、工作室报价页；
- 平台型产品本身，例如排行榜、导航站、工具站、API 服务的文档站；
- 第三方社交平台的账号主页（微信公众号、小红书、即刻、知乎、X 等）；
- 采集站、镜像站、SEO 伪原创站；
- 由 AI 批量生成、没有个人见解的内容农场；
- 含欺诈、恶意跳转、侵权或违法内容的站点。

### 判断时我们看这几件事

1. **背后有真人。** 能看出作者是谁、在持续写什么或做什么，而不是没有署名的空壳。
2. **内容是自己的。** 有原创文章、笔记或作品，不是聚合与转载。
3. **已经有内容。** 站上至少有几篇原创内容或几件作品，不是刚搭好的空站。
4. **用来表达和积累，不是用来推销。** 作品集展示的是作者自己，而不是一项待售的产品或服务。
5. **能正常访问。** 打得开、读得下去，没有弹窗轰炸或恶意跳转。

不要求自有域名。`github.io`、`pages.dev`、`vercel.app` 等托管地址同样可以收录。

> 简单说：**如果你把这个站点当作自己长期写作或创作的地方，它就属于这里。**

### 关于内容边界

收录不代表背书。站内观点属于各自的作者，我们不审查观点，只确认站点符合上面的标准。若某个站点后来变成营销页、被转手，或出现欺诈内容，欢迎通过 [数据纠错](https://github.com/realchendahuang/one-person-one-site/issues/new?template=data-fix.yml) 指出，我们会重新评估。

## 怎么用这份目录

**在网页上找。** 打开 [在线目录](https://realchendahuang.github.io/one-person-one-site/)，可以按标签筛选、全文搜索（站名、作者、简介都能搜），或者点「随机打开一个站点」去一个陌生人的站点看看。[完整目录页](https://realchendahuang.github.io/one-person-one-site/directory/) 按标签和名称列出了全部条目。

**批量订阅。** 下载 [feeds.opml](https://realchendahuang.github.io/one-person-one-site/feeds.opml) 导入任意 RSS 阅读器，就能一次性订阅所有提供 RSS 的收录站点。这比收藏夹更可靠，作者一更新你就能看到。

**复用数据。** 全部收录数据在 [data/sites.json](./data/sites.json)，线上地址是 [sites.json](https://realchendahuang.github.io/one-person-one-site/data/sites.json)，以 MIT 许可开放。拿去做可视化、做推荐或接进别的工具都可以。

## 提交你的网站

欢迎推荐新站点，尤其是那些还没被很多人发现的。提交前请先对照一下 [收录标准](#收录标准)。

**方式一：Issue 表单（推荐）**
打开 [**提交网站表单**](https://github.com/realchendahuang/one-person-one-site/issues/new?template=submit-site.yml)，填写网站名称、网址、站长名和一句话简介。维护者会校验格式、探测站点能否访问，通常**一两天内**处理完，结果会回复在你的 Issue 里。

**方式二：Pull Request**
1. Fork 并 Clone 仓库；
2. 在 `data/sites.json` 末尾追加你的站点：
   ```json
   {
     "name": "你的站点名称",
     "url": "https://your-domain.com",
     "owner": "你的昵称",
     "description": "一位后端工程师的技术博客，记录分布式系统与数据库的实践笔记。",
     "languages": ["zh-CN"],
     "region": "China",
     "tags": ["blog", "developer", "notes"],
     "feed": "https://your-domain.com/rss.xml"
   }
   ```
3. 运行 `python3 scripts/validate.py && python3 scripts/generate_directory.py`；
4. 提交 PR。

> `feed` 可以不填。如果站点有 RSS / Atom，请填上，它会让你的站点进入订阅合集。

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 站点全称或常用名，不超过 40 个字符 |
| `url` | ✅ | 首页地址，不要填某一篇文章 |
| `owner` | ✅ | 站长或创作者的常用名 |
| `description` | ✅ | 15~240 个字符。用第三人称客观描述这是谁的站、主要写什么，不写「值得收录」这类话 |
| `languages` | ✅ | 内容主要语言，如 `zh-CN`、`zh-TW`、`en`、`ja` |
| `region` | ✅ | 所在地区，如 `China`、`Taiwan`、`Japan`、`US`、`Global` |
| `tags` | ✅ | 1~8 个全小写标签，多词用中划线（如 `indie-hacker`） |
| `feed` | ⬜ | RSS / Atom / JSON Feed 地址；有多个时可写成数组，最多 5 条 |

### 推荐标签

| 分类 | 标签 |
|---|---|
| **内容形态** | `blog` · `digital-garden` · `notes` · `portfolio` · `newsletter` |
| **作者身份** | `developer` · `designer` · `writer` · `maker` · `indie-hacker` · `photographer` · `researcher` |
| **主题** | `ai` · `open-source` · `security` · `devops` · `game` · `tech` · `life` |

请尽量从这张表里选。用了表外的标签不会被拒，但 `validate.py` 会给出提示，维护者可能会帮你换成相近的推荐标签。

## 参与维护

- **发现站点失效？** 维护者会定期用巡检脚本检查收录站点能否访问，也欢迎通过 [数据纠错](https://github.com/realchendahuang/one-person-one-site/issues/new?template=data-fix.yml) 直接告诉我们。
- **信息需要修正？** 简介、标签、RSS 地址都可以改，提 Issue 或 PR 均可。
- **想讨论收录边界？** 在 Issue 里说明你的判断依据，我们愿意听。

详细流程见 [CONTRIBUTING.md](./CONTRIBUTING.md)。
